Read `AGENTS.md` first: it holds the invariants (Lovable sync, single AI provider, one publish path, tenant/billing boundaries). Subfolders may have their own `AGENTS.md` / `CLAUDE.md` (`src/lib/builder/`, `supabase/`); read them before editing there. This file covers how to work here cheaply and safely.

## Architecture (one screen)
- TanStack Start (React 19) + Vite + Tailwind v4, deployed on Cloudflare Workers. Routes: `src/routes/` (metadata via `head()`); `*.server.ts` = server-only, `*.functions.ts` = server functions.
- Supabase Postgres with RLS per workspace (`organization_id` + `private.is_org_member`). Migrations: `supabase/migrations/`.
- AI: Lovable AI only, through `src/lib/ai/router.server.ts`. Never add a second provider lane.
- Website builder: `src/lib/builder/` (plan → compose → validate → apply → QA → publish). Renderer: `src/components/site/CompositionRenderer.tsx`. Publish: only `publishSiteNow` in `production.functions.ts`.
- Durable work: `src/lib/site-engine.worker.server.ts` + `builder_chat_jobs`; never run builds inside a browser request.

## Commands (smallest first)
- One test: `npx vitest run src/path/to/file.test.ts` (or `bunx vitest run …`)
- Types: `NODE_OPTIONS=--max-old-space-size=6144 npx tsc --noEmit` (default heap runs out)
- Lint changed files only: `npx eslint path/to/file.ts`
- Prompt snapshots: `npm run test:prompts` (see `src/lib/builder/CLAUDE.md`)
- Full suite only before a push: `npx vitest run --exclude src/lib/flows.e2e.test.ts --exclude ".claude/**" --exclude "**/node_modules/**"`
- Package manager: CI installs with `npm install`; `bun install --frozen-lockfile` in `base-branch-guard`. Don't add packages without asking (bunfig enforces a 24h release-age guard).

## CI (`.github/workflows/quality-gate.yml`, runs on PRs to `lovable-sync`)
`typecheck` → `security:audit` (+ `:test`) → RPC/migration/browser-journey/Jarvis MCP contracts → `lint` → `repo:audit`, `repo:visual-output`, `builder:ultimate-audit`, `repo:audit:test` → `production:readiness`, `production:readiness:max`, `production:controls` → `test:coverage` → `build` → `client-bundle-guard`. Reproduce locally with the `run-ci-locally` skill; triage with `triage-ci-failure`.

## Conventions
- TypeScript strict with `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes`; use `@/` imports.
- Keep each change to the task; add or update the nearest `*.test.ts`. Never skip, disable or loosen a test to get green.
- Secrets never in code or logs; `.env*` is off-limits to reads.
- Claims about runtime behaviour need evidence (test output, CI run), not assumptions.

## Working cheaply
- Search narrowly (`rg -n -m 10 pattern path/`), read ranges, not whole files.
- Delegate wide searches to the `explorer` subagent and test runs to `test-runner` (both on a cheaper model; see `.claude/agents/`).
- MCP: `serena` for symbol-level reads/edits and project memories (`.serena/memories/`), `context7` for library docs, `playwright` and `chrome-devtools` (Lighthouse, performance traces, Core Web Vitals) for browser checks, `revora-jarvis-readonly` for bounded repo reads and CI status.
- Skills live in `.claude/skills/` (vendored ones carry `LICENSE` + `ATTRIBUTION.md`).
