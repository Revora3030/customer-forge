# Remove the last built-in looks, so the AI designs everything

The last cleanup removed the nine old design steps. A new scan of the whole codebase found more built-in looks from before your AI keys were connected. These are fixed colors, fonts, style lists and effect menus. Most still shape what a new site can look like. This plan removes all of them. It keeps only safety checks and a reader, so existing customer sites keep showing as they do now.

## What the scan found (still active)

1. **The style library** (`design-directions.ts`, 1,236 lines): ready-made looks such as "Luxury gold", each with fixed colors, a font and effects, matched to industry words. The Brand Choices picker and the AI composer both still offer or read these looks.
2. **The fixed font list** (`SITE_HEADING_FONTS`): the AI planner and the site agent are told to pick only from this list.
3. **The fixed effect menus**: backdrops (`BACKDROPS`) and section effects (`SECTION_EFFECTS`). The AI can only choose effects from these menus.
4. **The old layer designer** (`visual-composition.ts`, 970 lines): a layer library, a "creative commands" list, a keyword reader for prompts and a rule-based "invent a composition" step. None of these use AI.
5. **The homepage concept** (`homepage-concept.ts`): a composition made by that rule-based step.
6. **Default brand colors**: new clients start with green, navy and amber (`#34d399` / `#0f172a` / `#fbbf24`). Onboarding starts with black and gold. The worker treats the green as "not chosen yet".
7. **Fixed size scales** (`site-style.ts`): only certain text sizes, spacing, corner rounding and widths are allowed.
8. **Preset quick buttons** (`builder-modes.ts`): builder shortcuts with pre-written style requests.

## What gets built instead

- **Style library:** removed. Brand Choices becomes: light or dark, your own colors, your own font name (optional), plus "let the AI decide". The AI composer no longer looks up a preset.
- **Fonts:** the AI can name any font. A safety check confirms the font loads from Google Fonts. If it doesn't, the AI is asked to choose again. We never swap in a font of our own.
- **Effects:** the AI writes its own backdrop and motion settings as safe CSS values (gradient stops, blur, opacity, timing). These are checked for contrast, reduced-motion support and phone performance. The old effect names stay readable only so existing sites keep showing.
- **Layer designer:** the rule-based parts (commands, keyword reader, invent step, originality score) are deleted. Only the safe-read and safe-save of stored layers stays.
- **Homepage concept:** the Revora marketing homepage keeps its current look, saved as fixed data. It will no longer be generated by the old rule step.
- **Default colors:** removed. New clients and onboarding start with no colors, and Sol picks them on the first build unless the owner picks their own. The "green means unset" check is replaced with a real empty check.
- **Size scales:** the fixed steps become safe ranges (for example, text from 10 to 200px), so the AI can use any value inside a range.
- **Quick buttons:** they send your plain request to the AI with no pre-written style wording. Every design decision stays with the AI.

## Kept on purpose (safety only)

Fact checks, security and access rules, billing, contrast and touch-size minimums, one column on phones, reduced motion, restore points, cost caps, publish checks, and read-only display of looks existing sites have already saved.

## Steps (each must pass the full check before the next)

1. Confirm whether the database gives new sites a built-in color. If it does, remove that default with a safe change that keeps existing data.
2. Remove the default brand colors (steps 6 and 1).
3. Open up fonts, with the load-safety check.
4. Replace the effect menus with AI-written, safety-checked settings, plus a legacy reader.
5. Change the size scales into safe ranges.
6. Delete the style library and simplify Brand Choices and the AI composer.
7. Remove the rule-based parts of the layer designer, and freeze the homepage concept as data.
8. Strip the pre-written style wording from the quick buttons.
9. Extend the guard tests, so the build fails if any preset look, font list, effect menu, default color or rule-based composer comes back.
10. Full check: type check, lint, all tests and a production build. Then load an existing site and a fresh AI build at phone, tablet and desktop sizes.

## Technical details

- Deleted: `src/lib/design-directions.ts` and its tests. Deleted from `src/lib/visual-composition.ts`: `LAYER_LIBRARY` choice logic, `CREATIVE_COMMANDS`, `interpretVisualPrompt`, `inventComposition`, `seedPromptFor`, `originalityScore`.
- Edited: `site-theme.ts` (font list becomes a safety check only), `site-agent.server.ts` and `ai-agent-plan.server.ts` (no font list in the instructions), `site-effects.ts` (legacy ID reader, plus a new validated effect spec), `site-style.ts` (ranges), `builder-modes.ts`, `BrandChoices.tsx`, `ai-composition.server.ts`, `ai-brand-identity.server.ts`, `NewClientDialog.tsx`, `onboarding.tsx`, `site-engine.worker.server.ts`, `homepage-concept.ts`, `SiteSections.tsx`, `SiteBackdrop.tsx`, `DecorativeArt.tsx`, `authority-firewall.test.ts`.
- Not touched: email templates, error pages and the Revora marketing site's own brand colors. These are your company's branding, not the customer site builder.
- Trade-off: when every AI model is down, a new build shows a clear "try again" message. Nothing gets a stand-in look.
- Nothing reaches live sites until you publish.
