# Complete the 58 remaining Customer Forge upgrades

## Goal
Finish the remaining builder work without weakening tenant isolation, auth, billing, publishing, rollback, literal wording, factual safeguards, or the $0 external-AI rule for customer website building.

## Delivery order

### A. Native intelligence and safety foundation (steps 1–18)
- Remove all external-model dispatch from customer build and edit paths.
- Add a native synthesis stage that combines industry strategy, buyer intent, conversion goals, creative direction, design fingerprints, information architecture, content constraints, and factual provenance.
- Add deterministic adversarial reviews for facts, literal directives, conversion continuity, navigation, uniqueness, accessibility, SEO, and incomplete pages.
- Persist the selected strategy, validation outcomes, synthesis rationale, timing, and evidence using organization-scoped records with strict access controls.
- Add caching, deduplication, concurrency limits, capability health, and failure isolation for optional operator diagnostics.
- Fix free-provider failover so one invalid candidate cannot incorrectly stop the whole diagnostic chain.

### B. Luna boundary and budget controls (steps 19–24)
- Keep Luna completely outside customer generation, editing, repair, approval, and readiness decisions.
- Allow Luna only as an explicitly enabled operator diagnostic, with its existing hard monthly ceiling and no automatic top-up.
- Add regression tests proving customer builds cannot call Luna or another external model, even when keys are configured or native analysis fails.

### C. Complete, differentiated first builds (steps 25–39)
- Make fresh sites complete and editable: home, services, about, contact, plus only supporting pages justified by customer intent.
- Give every page a clear job, conversion action, search intent, content-depth target, and route from navigation or another page.
- Drive shell, navigation, hero, section order, grids, type, spacing, surfaces, borders, backgrounds, imagery, footer, transitions, and CTA patterns from the full design fingerprint.
- Add cross-site uniqueness checks and industry-specific creative direction without random styling.
- Use imagery in this order: customer assets, licensed stock, verified zero-cost generation, truthful abstract artwork.
- Never fabricate business photography, testimonials, credentials, awards, prices, results, statistics, guarantees, or integrations.
- Record field-level provenance, preserve exact customer wording, show `UNKNOWN` for required missing facts, and regenerate only safe unlocked sections.
- Validate all contact, quote, booking, phone, and CTA destinations.

### D. Enforced first-preview quality gate (steps 40–51)
- Enforce: materialize → real render → inspect → screenshot → review → safe repair → rerender → recheck → final evidence.
- Test every generated page at 320, 375, 390, 414, 768, 1024, 1280, and 1440 pixels.
- Detect overflow, clipping, overlap, sticky-element collisions, long-word failures, touch targets, keyboard/focus issues, landmarks, headings, labels, contrast, reduced motion, console errors, failed requests, and broken resources.
- Measure real Core Web Vitals and page budgets rather than recording placeholders.
- Validate metadata, canonical tags, Open Graph, schema, sitemap, indexability, conversion paths, factual completeness, and stranded pages.
- Use only native screenshot analysis in the customer build gate. External visual reviewers remain optional, operator-only diagnostics whose findings are treated as untrusted.
- Create a restore point before repair; keep a repair only when before/after evidence improves; cap repair loops and surface unresolved blockers.
- Never mark a preview ready while required evidence is missing.

### E. Builder Experience 2.0 completion (steps 52–56)
- Stream calm progress stages and show a compact evidence summary.
- Link each finding to its page and element with one plain-language repair action.
- Complete visual-edit round trips: select, adjust, preview, Apply/Cancel, persist, Undo/Redo, reload, and rollback.
- Add image upload, licensed search, crop/focal point, alt text, replace, remove, and provenance controls.
- Keep image editing unavailable until a genuinely zero-cost edit-capable model passes a live capability test.
- Add before/after comparison while preserving drafts, branches, versions, publishing safeguards, and mobile usability.

### F. Production proof (steps 57–58)
- Add durable end-to-end journeys covering fresh customers, varied industries, five-page navigation, all eight widths, visual edits, provider failures, malformed diagnostic output, zero-cost enforcement, image fallback, readiness gates, accessibility, SEO, performance, tenant isolation, secret leakage, drafts, rollback, and publishing safety.
- Run targeted and full tests, type checks, lint/build checks, dependency and security audits, authenticated browser journeys, database isolation attacks, and available integration checks.
- Report exact evidence, changed files, commit SHA, and only blockers reproduced in the real environment.
