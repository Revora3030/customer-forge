# Full-site first-build quality upgrade

## Goal
Make every new Customer Forge website feel deliberately designed from the first screen through the footer, across every generated page—not just the home page or hero image. The recording is a quality and interaction reference, not a template to copy: each industry keeps its own visual language, content hierarchy, imagery, and conversion path.

The builder will continue to use Revora’s native deterministic engine for website building, preserve tenant and publishing safety, and never invent reviews, results, prices, certifications, offers, staff, business photos, or before/after proof.

## What will change

### 1. Compile a complete site campaign before building pages
- Upgrade the creative contract from section-level styling to a versioned site campaign covering navigation, announcement/service-area bar, page openings, type hierarchy, color roles, section rhythm, cards, media roles, forms, mobile action bar, footer, and motion.
- Compile a page-specific story for every page: purpose, buyer question, primary action, required facts, sections, image roles, internal links, and mobile order.
- Keep industry archetypes genuinely different: automotive, trades, clinics, restaurants, professional services, property, hospitality, retail, fitness, care, pets, industrial, creative, and other supported businesses receive appropriate page structures rather than renamed copies of one layout.
- Make screenshot/video references influence bounded composition traits while blocking copied logos, wording, identity, and unsupported claims.

### 2. Build every page as a complete conversion journey
- Expand first-build materialization so home, service index, each service page, about, pricing, areas/location, contact, booking/quote, gallery/work, FAQs, and archetype-specific pages each receive a deliberate opening, body narrative, proof or trust where real evidence exists, contextual action, and closing section.
- Add meaningful content depth from supplied facts: service details, process, suitability, areas, pricing, FAQs, contact options, booking requirements, and next steps. Missing facts remain absent or clearly request owner input.
- Create safe page-to-page journeys: service cards link to service pages; service pages link to relevant booking/quote/contact paths; pricing and area pages link back to services; every visible page remains reachable through navigation or contextual links.
- Add truthful fallbacks. Before/after comparisons, reviews, team profiles, credentials, project galleries, and statistics appear only when matching owner-provided evidence exists.

### 3. Give all important section types dedicated premium compositions
- Replace the generic text fallback for intro, about, area, guarantee, offer, lead capture, and policy content with dedicated renderers.
- Upgrade service-detail pages to use their assigned media and support editorial text/media, sticky action, price, process, FAQ, and closing-action compositions.
- Add composition families for service grids, pricing, process, trust bars, benefits, galleries, verified reviews, areas, FAQs, forms, contact, booking, quote, and CTAs.
- Make the stored creative contract control actual markup and layout—not only class names—including media position, focal crop, heading treatment, density, mobile order, and section transitions.
- Keep cards restrained and purposeful; use full-width bands, editorial grids, image-led sections, and strong whitespace instead of putting every section in a floating panel.

### 4. Make the header, navigation, footer, and mobile conversion system site-wide
- Build a brand header that can use the real logo, business name, service area, primary action, and compact mobile menu without crowding.
- Support desktop and mobile navigation patterns selected by the site campaign, including active states and nested service destinations when needed.
- Build a richer footer from real facts: brand summary, page groups, contact methods, service area, social links, and required legal links.
- Preserve a two-action mobile bar only when both actions are real; otherwise use one clear action. Respect safe-area insets and never cover form controls or footer content.

### 5. Plan and attach imagery across the whole site
- Replace the six-image/site ceiling with a bounded page-aware inventory sized to visible page needs, while deduplicating reusable campaign images.
- Assign owner media by explicit role first, then request safe generated marketing visuals only for uncovered eligible roles; do not let one upload suppress the rest of the site’s imagery.
- Attach media to interior-page openings, service detail bodies, CTAs, category pages, and other planned placements—not merely the home hero and service cards.
- Make service-detail rendering consume its assigned image. Preserve subject-aware alt text, focal points, mobile crops, provenance, credits, and safe cleanup.
- Execute bounded image repair plans for rejected/missing assets. If image generation is unavailable, use honest Revora artwork or an image-free composition and report the limitation—never fake completed work.

### 6. Add reference-level interactions only when supported by real data
- Add a polished quote/booking form composition, service selectors, date fields, and clear submission states using existing lead capture.
- Add before/after comparison only for an owner-supplied matched pair; otherwise omit it.
- Add expandable FAQs, mobile menu behavior, contextual calls/text links, media interactions, and restrained reveal motion with reduced-motion support.
- Ensure forms, menus, comparisons, and sticky actions are keyboard accessible and have stable dimensions.

### 7. Enforce site-wide richness and consistency before review
- Add a deterministic quality contract for every visible page: complete opening, enough useful depth, real action destination, metadata, internal navigation, suitable media or intentional image-free layout, accessible names, and no filler.
- Add cross-page checks for repeated anatomy, duplicate copy, visual monotony, inconsistent action labels, missing images, orphan pages, weak footers, and unsupported evidence.
- Score only measurable output. Static checks remain distinct from browser/perceptual, mobile, performance, and interaction evidence.

### 8. Run a real inspect → repair → re-inspect loop
- Extend safe auto-repair beyond metadata and broken links to deterministic layout and media fixes: missing assigned media, invalid crop settings, overflow-prone compositions, duplicate sections, incomplete page endings, and inconsistent action targets.
- Execute rendered browser checks for every visible page at 320, 390, 768, 1024, 1280, and 1440 widths; capture overflow, broken resources, console errors, layout shift, interactions, and screenshots.
- Add perceptual grading for visual density, hierarchy, spacing, repetition, image coverage, and cross-page consistency; keep unmeasured areas marked not verified.
- Re-run checks after each bounded repair. Block publication on unresolved critical failures and preserve rollback for fresh replacements.

### 9. Remove bypasses and preserve production safety
- Route legacy/template-only output through the same premium site shell or migrate it safely so it cannot bypass the complete renderer contract.
- Make first-build materialization transactional or explicitly compensating: clean only newly generated rows/media on failure and restore fresh-rebuild backups when required.
- Preserve authorization, organization isolation, billing, analytics event definitions, custom domains, publishing, and existing customer websites.
- Add migrations only if unavoidable, with explicit grants and row policies in the same migration.

## Validation
- Unit tests for campaign compilation, page-story planning, truthful evidence gates, image-role assignment, all archetype page structures, navigation, and repair decisions.
- Integration tests proving every supplied service receives a complete linked landing page and every generated page satisfies the minimum quality contract.
- Browser journeys covering menus, every visible internal link, forms, FAQ controls, sticky actions, before/after when eligible, and no mobile overlap.
- Visual regression evidence across the required widths for representative industries, with no console/runtime errors or broken assets.
- Full project tests, type checks, lint/build checks, security checks for affected boundaries, and fresh-build rollback verification.

## Delivery sequence
1. Site campaign and page-story contracts.
2. Full-page materialization and truthful content depth.
3. Dedicated renderers plus global header/footer/mobile system.
4. Page-aware media inventory, attachment, repair, and cleanup.
5. Site-wide quality contract and cross-page consistency checks.
6. Browser/perceptual repair loop and publication gate.
7. Representative fresh builds, regression fixes, and final verification.

## Acceptance criteria
- A fresh build creates a coherent multi-page website where every visible page has a deliberate purpose, premium composition, useful real content, and working conversion path.
- Interior pages visibly share the brand system but do not repeat the home page’s exact anatomy.
- The first build adapts to the business type rather than applying the recording’s automotive styling universally.
- No unsupported review, result, before/after, price, credential, team member, project, or integration is shown.
- All visible pages pass deterministic checks; critical browser failures prevent publication; unexecuted checks remain explicitly not verified.
