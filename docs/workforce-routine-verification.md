# Scheduled workforce claim hardening

The existing cron runner now conditionally updates the unchanged enabled owner-scoped routine before message insertion or Jarvis dispatch. Its existing `last_run_at` consumes the local scheduled day; the `running` status and unique attempt marker fence completion. No schema, new executor, scheduling frequency, provider, budget or approval changes.

Losing claim races dispatch nothing. Claim errors fail closed. Settlement errors or lost rows report completion unconfirmed rather than success; an unresolved running attempt blocks later scheduled attempts, including across local midnight. Successful settlement does not move the consumed occurrence into the completion day. Existing daily Eastern and Monday weekly behavior remains.

This provides conditional-update concurrency protection for this runner, not exactly-once provider delivery or serialization across different routines and interactive chat. An unresolved attempt needs explicit owner reconciliation; no automatic lease expiry or paid retry is introduced. Existing owner permissions are unchanged. Old deployed workers do not honor these claims, so no mixed-version rollout guarantee is claimed.

Tests use shared in-memory conditional-update state and an injected executor. They cover concurrent passes, claim failure/identity substitution, edited prompts, failed execution, failed or zero-row settlement, next-day blocking, next-day settled eligibility and the existing pass bound.
