# Autonomous Builder 2.0 Contract\n\nCustomer Forge now has a deterministic orchestration layer above the existing builder engines.\n\n## Operating loop\n\n1. Understand the natural-language request.\n2. Build a site/context graph from the available workspace state.\n3. Classify the requested engineering phases.\n4. Detect architecture, content, conversion, SEO, accessibility, responsive and performance risks.\n5. Generate only actions supported by the existing AgentAction contract.\n6. Keep unknown facts as questions or blocked findings instead of inventing them.\n7. Pass all actions through the existing elite plan guard.\n8. Execute through the existing site-agent boundary.\n9. Verify with deterministic checks.\n10. Hand runtime-only checks to the browser/runtime verification layer.\n11. Isolate failed action groups rather than blindly replaying a full plan.\n12. Restore the last known-good snapshot when a safe repair cannot be proven.\n\n## Capability matrix\n\n| Capability | Static/deterministic | Runtime evidence |\n| --- | --- | --- |\n| Natural-language phase decomposition | Yes | No |\n| Site structure analysis | Yes | No |\n| Duplicate slug detection | Yes | No |\n| Placeholder detection | Yes | No |\n| CTA coverage | Yes | Form submission still requires runtime |\n| Metadata repair | Yes | Search-engine validation remains external |\n| Semantic accessibility checks | Yes | Contrast/keyboard/screen-reader need runtime |\n| Responsive risk detection | Yes | Actual viewport comparison needs runtime |\n| Performance complexity | Yes | Core Web Vitals/network waterfall need runtime |\n| Security boundary reporting | Yes | RLS/auth adversarial proof needs environment |\n| Browser navigation | Boundary only | Required |\n| Console/runtime errors | Boundary only | Required |\n| Visual regression | Boundary only | Required |\n| Form submission | Boundary only | Required |\n| Production telemetry | Boundary only | Required |\n| Backup/restore verification | Boundary only | Required |\n\nThe distinction is intentional. Autonomous QA systems are more reliable when an agent plans and interprets while deterministic browser tests remain the release gate.\n\n## Safety contract\n\nThe operating system does not:\n- execute arbitrary JavaScript;\n- call a new AI provider;\n- invent prices, reviews, credentials, guarantees or business results;\n- bypass RLS, authentication, Stripe, billing or publishing boundaries;\n- claim a browser check passed when no browser evidence exists.\n\nThe existing executor and final elite plan guard remain authoritative.\n\n## Target end state\n\nUNDERSTAND → INSPECT → PLAN → BUILD → VERIFY → DIAGNOSE → REPAIR → RE-VERIFY → RECOVER → PUBLISH\n\nThe current implementation makes the planning, deterministic repair and evidence boundaries explicit. Real browser execution and production infrastructure remain separate capabilities and must be connected to their respective runtime systems before they can be truthfully marked as live.
